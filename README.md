# Senko Assistant 2.2.1: ключи только на сервере

`README.md` и `changes.diff` в репозиторий не копируются.

## Что нашла на GitHub
- **В коде и в истории коммитов ключей нет.** Я проверила все коммиты репозитория `Kofemanchik/Senko-Assistant`. Искала токены Telegram, GitHub, Supabase, Google, Groq и OpenRouter, приватные ключи и пароли. Ничего не нашлось. В `server-config.js` лежит только публичный ключ Supabase (anon). Он и должен быть в программе, данные защищены правилами доступа в базе. В логах GitHub Actions секреты скрыты звёздочками.
- **Утечка в установщике.** Workflow «Build installer» записывал два секрета в файлы `laws-key.json` и `ai-key.json`, а они попадали внутрь `.exe`. Установщики лежат в открытых Releases. Любой, кто распакует программу, достанет:
  - `LAWS_KEY`, ключ расшифровки законов;
  - `AI_KEY`, ключ доступа к ИИ-прокси. С ним можно задавать вопросы ИИ в обход программы и тратить твой лимит.
- Спрятать ключ внутри программы нельзя: программа должна им пользоваться, значит его можно достать. Поэтому в 2.2.1 ключей в программе нет совсем.

## Что изменилось в 2.2.1
- **Законы.** Программа, как раньше, сверяет `laws-status.json` на GitHub. Тексты теперь получает с сервера Senko (Supabase), он расшифровывает `laws.enc` своим ключом. Нужен вход в аккаунт, без входа программа повторит попытку через минуту. Уже скачанные законы, история и откат работают как раньше.
- **ИИ-помощник.** Вопрос уходит на сервер Senko. Сервер подписывает запрос к ИИ-прокси, пишет вопрос в журнал (`/ailog`) и возвращает номер записи для 👍/👎. Без входа ИИ отвечает «Войдите в аккаунт». Ответ про создателя остался в программе и на сервер не уходит.
- **Общий лимит ИИ.** Лимит прокси (`DAILY_PER_USER`, по умолчанию 15 в день) теперь считается на аккаунт, вместе с сайтом. Раньше он считался на компьютер и IP. Сервер дополнительно не пускает больше 60 запросов в день с одного аккаунта.
- **Сборка.** Шаги с ключами из `build.yml` убраны, файлы ключей убраны из `package.json`. Новый шаг «Проверка, что ключей нет в сборке» остановит сборку, если ключ законов окажется внутри программы.
- **`.gitignore`** в корне. `laws-key.json`, `ai-key.json`, `node_modules` и `dist` больше не попадут в коммит случайно.
- **Workflow «Rekey laws»** (`.github/workflows/rekey-laws.yml`) перешифровывает `laws.enc` новым ключом. Он нужен в шаге 3.
- В «Что нового» добавлена запись 2.2.1, из неё же соберётся текст релиза.

## Шаг 3. Новые ключи
Старые ключи считаем раскрытыми, поэтому заводим новые. Значения старых знать не нужно.

**3.1. Придумай два ключа.** Выполни в PowerShell два раза и сохрани обе строки у себя (ключ А для ИИ, ключ Б для законов):
```powershell
$b = New-Object byte[] 32; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); -join ($b | % { $_.ToString("x2") })
```
Ключи вводи только в настройках ниже и никому не присылай, мне тоже.

**3.2. ИИ (ключ А).**
```powershell
cd "C:\senko-assistant\worker"
npx wrangler secret put APP_KEY
npx wrangler deploy
```
На вопрос wrangler вставь ключ А. Если раньше заводил `WEB_KEY`, удали его: `npx wrangler secret delete WEB_KEY`.

Затем Supabase → **Edge Functions** → **Secrets**: `AI_KEY` = ключ А.

**3.3. Законы (ключ Б).**
1. GitHub → репозиторий → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**: `LAWS_KEY_NEW` = ключ Б.
2. Supabase → **Edge Functions** → **Secrets**: `LAWS_KEY` = ключ Б.
3. GitHub → **Actions** → **Rekey laws** → **Run workflow**. Дождись зелёной галочки. Workflow перешифрует `update/laws.enc` ключом Б.
4. Сразу после этого: секрет `LAWS_KEY` → **Update** → ключ Б. Затем удали `LAWS_KEY_NEW`. Ночная проверка форума дальше работает с ключом Б.

**3.4.** На GitHub удали секрет `AI_KEY`: сборке он больше не нужен.
