# Судебный портал (court-portal)

Самостоятельный сайт судебной помощи для Majestic RP с двумя серверами: **San Francisco** и **Orlando**. Иски собираются в готовый BB-код для форума, дальше их ведёт судебная панель. Прокуратура и IID работают в той же панели.

Папка полностью изолирована от программы Senko Assistant и её сайта: свои файлы, свои таблицы (все с префиксом `cp_`), общего кода нет. Рекомендуется завести для неё **отдельный проект Supabase**.

## Что умеет (этап 1: иски и кабинет)

**Публичный сайт** (`public/`)
- Переключатель сервера вверху страницы. Суды, законы, решения, заседания и анкеты показываются для выбранного сервера.
- Подача иска в три шага (кто и куда → суть → проверка) с автосохранением черновика. На выходе номер иска, код отслеживания, **BB-код** и инструкция, как вставить его на форум. Ссылку на созданную тему можно прикрепить к иску.
- Статус иска по номеру или коду: стадия, судья, заседание, сообщение суда. По коду можно отправить ходатайство или доказательства.
- Кабинет: свои иски (в том числе где вы истец или ответчик по статику персонажа), материалы и их статусы, до трёх персонажей на каждом сервере, профиль.
- Заседания, справочник законов, реестр решений, анкета на работу в суде.

**Судебная панель** (`public/panel/`)
- Вход по логину и паролю (или по почте). Первый зарегистрированный сотрудник становится администратором.
- Роли: администратор, председатель, судья, секретарь, ГП/ЗГП, прокурор, начальник IID, сотрудник IID. Сотрудников и их сервер назначает администратор.
- Иски: реестр, «взять в работу», назначение судьи, стадии, заседания (с предупреждением о пересечении по времени), приём и отклонение материалов, заметки суда, сообщение заявителю, завершение с исходом, решение по иску, запрос прокурора. Сроки (взять в работу, ответ прокуратуры, решение) подсвечиваются в «Обзоре».
- Прокуратура: ГП/ЗГП разбирают запросы суда и назначают прокурора, прокурор видит свои иски и отмечает «Участие завершено».
- Дела суда, IID и прокуратуры: создание, проверка начальником, возврат на доработку, передача IID → прокуратура → суд, журнал движения дела.
- Решения, заявки на работу, законы, пользователи, настройки (суды и ссылки на разделы форума, категории, госпошлина, сроки, анкета, политика), журнал действий.
- **Discord-вебхуки** на 10 событий. Кнопка «Проверить» шлёт тестовое сообщение.

## Серверы
- Суды привязаны к серверу, номер иска строится от кода суда (`SFDC-1`, `ORDC-1`).
- Иски, дела, решения, заявки, персонажи и сотрудники имеют сервер. Сотрудник с привязкой видит данные только своего сервера, администратор (и сотрудник без привязки) — оба, с переключателем в шапке панели.
- Статик персонажа действует в пределах сервера: один и тот же номер на другом сервере не даёт доступа к чужим искам.

## Безопасность в двух словах
- Доступ к данным ограничен правилами базы (RLS), а не скрытием кнопок. Ключ `anon` в `config.js` публичный, это нормально.
- Адреса вебхуков лежат в таблице, которую читает только администратор. Сообщения отправляет сама база (`pg_net`), пинги `@everyone` и ролей отключены.
- Публичные отправки (иск, заявка, материал) идут через функции с ограничением частоты.
- Тексты вставляются как текст, а не как HTML; BB-теги в пользовательском тексте обезвреживаются. В `public/_headers` задана строгая политика CSP.

## Запуск

### 1. База (Supabase)
1. Создайте проект на supabase.com.
2. **SQL Editor** → вставьте весь файл `supabase/schema.sql` → Run. Скрипт рассчитан на чистую базу и безопасен при повторном запуске.
3. **Authentication → Providers → Email**: выключите **Confirm email**. Вход идёт по логину: к нему дописывается служебный домен `LOGIN_DOMAIN` (письма не отправляются).
4. **Project Settings → API**: скопируйте *Project URL* и ключ *anon public*.

### 2. Сайт
1. В `public/assets/config.js` впишите URL и anon-ключ. Если Supabase отклоняет служебную почту, поменяйте `LOGIN_DOMAIN`.
2. Локально: `cd public && python3 -m http.server 8080`, затем http://localhost:8080 и http://localhost:8080/panel/.
3. Публикация: любой статический хостинг. Cloudflare Pages: *Build command* пустой, *Build output directory* — `court-portal/public`.
4. Поддомен `panel.ваш-домен` на тот же проект сам переправит в панель.

### 3. Первый вход
1. `/panel/` → «Создать аккаунт сотрудника»: вы станете администратором.
2. **Настройки**: проверьте суды обоих серверов, впишите ссылки на разделы форума для подачи исков, категории, госпошлину, сроки, вебхуки Discord.
3. **Пользователи**: выдайте роли и сервер тем, кто зарегистрировался.
4. **Законы**: добавьте статьи для нужного сервера (или для обоих).

## Тесты
Схема проверена в Postgres (PGlite) 160 проверками: права по ролям и серверам, нумерация, workflow дел, Discord-события. Интерфейс проверен дымовыми тестами на jsdom с подставным клиентом Supabase. Скрипты тестов не входят в репозиторий.

## Структура
```
court-portal/
├─ supabase/schema.sql      таблицы, роли, правила доступа, вебхуки, функции публичных форм
└─ public/                  статический сайт
   ├─ index.html            сайт (#/claim, #/track, #/hearings, #/laws, #/decisions, #/guide, #/apply, #/cabinet)
   ├─ panel/                панель: panel.js, claims.js, cases.js, admin.js, ui.js
   ├─ assets/               config.js, common.js, bbcode.js, claim.js, app.js, style.css, boot.js
   ├─ _headers              заголовки безопасности
   └─ robots.txt
```
