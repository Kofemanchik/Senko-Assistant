# Senko Assistant: подключение серверной части (этапы 1–2)

Что в архиве и куда класть:

| Файл | Куда |
|---|---|
| `supabase/schema.sql` | вставить в Supabase (шаг 1) |
| `supabase/functions/senko/index.ts` | вставить в Supabase (шаг 2) |
| `.github/workflows/supabase-keepalive.yml` | в репозиторий `Kofemanchik/Senko-Assistant` |
| `main.js`, `preload.js`, `accounts.js`, `auth-preload.js`, `staff-preload.js`, `server-config.js`, `package.json` | в корень проекта программы, с заменой |
| `app/index.html`, `app/auth.html`, `app/staff.html` | в папку `app/` проекта, с заменой |

## 0. Сначала безопасность
Токен бота, который вы присылали в чат, считайте скомпрометированным. В @BotFather: `/mybots` → ваш бот → **API Token** → **Revoke current token**. Новый токен никому не показывайте и вводите только в шаге 3.

## 1. База данных
Supabase → **SQL Editor** → **New query** → вставьте весь `schema.sql` → **Run**. Ошибок быть не должно. Скрипт безопасно запускать повторно.

## 2. Серверная функция
Supabase → **Edge Functions** → **Deploy a new function** → **Via Editor**. Назовите функцию ровно `senko`, вставьте весь `index.ts`, нажмите **Deploy**.

**Важно:** у функции должна быть выключена проверка JWT (настройка **Verify JWT** / «Enforce JWT verification» → OFF). Приложение входит по своему токену и не отправляет JWT Supabase. Если оставить включённой, всё будет отвечать 401.

## 3. Секреты
Edge Functions → **Secrets** (Manage secrets) → добавьте три:

| Имя | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | новый токен бота из BotFather |
| `OWNER_TG_ID` | `8863080356` |
| `TG_WEBHOOK_SECRET` | придуманная вами длинная строка из латинских букв и цифр (32+ знака, без пробелов) |

Остальное (`SUPABASE_URL`, `SUPABASE_DB_URL`) Supabase подставляет сам. Если функция пишет, что нет строки подключения к базе, добавьте секрет `DB_URL` со строкой подключения: **Project Settings → Database → Connection string (URI)**, подставив пароль базы.

## 4. Подключение бота
Откройте в браузере (подставьте свой `TG_WEBHOOK_SECRET`):

`https://wcjspwailippjmyffkei.supabase.co/functions/v1/senko?setup=ВАШ_СЕКРЕТ`

Должно ответить `{"ok":true,...}`. Затем напишите боту `/start`: он покажет ваш Telegram ID и «Доступ: владелец». `/help` покажет команды.

## 5. Выпуск программы
1. В проекте уже `version: 1.6.0` в `package.json`. Соберите установщик (`npm run dist`) и опубликуйте релиз на GitHub как обычно.
2. **Папку `update/` с новым `index.html` пока не обновляйте.** Старые версии программы (1.5.x) подтянут новый `index.html` без нового `main.js` и покажут текст политики про сервер, а аккаунты у них по-прежнему локальные. Новый `index.html` уже внутри установщика 1.6.0 и дойдёт через автообновление.
3. Положите `supabase-keepalive.yml` в репозиторий и откройте **Actions → Supabase keep-alive → Run workflow**. Задание должно завершиться зелёным. Если репозиторий 60 дней без активности, GitHub отключает расписание: тогда включите его вручную.

## 6. Первый запуск
1. Запустите программу и зарегистрируйтесь. **Сохраните код восстановления** (он показывается один раз).
2. В Telegram придёт карточка регистрации.
3. Боту: `/role ВАШ_ЛОГИН owner`. В программе появится кнопка «Сотрудники» (Настройки → Аккаунт). Роль подтянется при следующем входе или в течение ~20 минут.
4. У тех, кто пользовался старой версией, при первом входе программа сама предложит **перенести локальный аккаунт**: логин, пароль и данные подставятся, останется добавить Discord и номер.

## Роли и видимость
| Роль | Что видит в списке сотрудников |
|---|---|
| Пользователь | только свои данные, списка нет |
| Руководство (`leader`) | ник, статик, организация, роль в игре, Discord, номер |
| Модератор (`moderator`) | то же + блокировки, «был в сети»; **без** Telegram |
| Владелец (`owner`) | всё, кроме паролей (их не видит никто) |

Роли выдаёт только владелец через бота. Модератор должен сначала написать боту `/start` и сообщить вам свой Telegram ID: `/role логин moderator 123456789`.

## Команды бота
- Все (владелец и модераторы): `/find текст`, `/user логин`, `/ban логин [причина]`, `/unban логин`, `/resets`
- Только владелец: `/role логин user|leader|moderator|owner [telegram_id]`, `/stats`, `/audit`
- Кнопки **Подтвердить / Отклонить** под запросами на сброс пароля.
- Ограничения: модератор не блокирует модераторов и владельца и не выдаёт роли; владельца заблокировать нельзя.

## Сброс пароля
Игрок вводит логин, ник и статик → если совпало, запрос уходит в Telegram владельцу и модераторам → после подтверждения игрок сам задаёт новый пароль. Если у игрока есть **код восстановления**, подтверждение не нужно (код после использования заменяется новым). Все старые сессии при сбросе завершаются.

## Что стоит знать
- Бан действует сразу: заблокированный не может войти, а открытое приложение закроется на ближайшей проверке (каждые ~20 минут).
- Без интернета запомненный вход работает до 14 дней по сохранённому профилю, затем нужна связь.
- Один статик можно указать у нескольких аккаунтов, но вам в Telegram придёт предупреждение «статик уже указан у…».
- Удалить аккаунт: SQL Editor → `delete from profiles where login_lc = 'логин';`
- Резервные копии: насколько мне известно, на бесплатном тарифе Supabase их нет. Периодически выгружайте таблицу `profiles` (Table Editor → Export to CSV).
- Данные работы (задержания, статистика тестов) на сервер пока не переносятся, это следующий этап.


## Этап 2: синхронизация между компьютерами и ИИ-помощник

**Если серверная часть уже подключена (этап 1), нужно только:**

1. В Supabase → SQL Editor выполнить заново весь `supabase/schema.sql` (он безопасен для повторного запуска, добавляет таблицу синхронизации).
2. Заново задеплоить функцию `senko` (вставить новый `supabase/functions/senko/index.ts`, Verify JWT оставить выключенным). Новых секретов не нужно.
3. Поднять версию, выпустить установщик 1.6.0 (тег `v1.6.0`) и только после этого трогать `update/`.

Синхронизируются: история задержаний, журнал, результаты тестов, статистика по вопросам, опыт и серия дней. Данные объединяются при запуске и отправляются через несколько секунд после изменения. При входе в другой аккаунт на том же компьютере данные прежнего аккаунта на сервер не уходят (копия кладётся в `Документы\Senko Assistant\Автономные копии`).

**ИИ-помощник** (ваша часть) вставлен без изменений: `ai.js`, `voice*.js`, `app/voice/`, `worker/`, `README-AI.md`, `.github/workflows/build.yml`. Для сборки нужен секрет GitHub `AI_KEY`.
